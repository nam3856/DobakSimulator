## 복구와 비용의 한계

일반 파괴 흔적은 `min(파괴 직전 별, 22)`를 저장합니다. 12성 복구는 같은 장비1개, 추가 메소0입니다. 별 보존 복구는 흔적18성 이하1개,19~20성2개,21성3개,22성4개와 레벨·단계별 메소를 사용합니다.

비용은 `JIJAKBI/rules/starforce.json`의 `kms-starforce-2026-08-20-beta-costs`를 원본 그대로 스냅샷으로 보관했습니다. 해당 프로젝트가 2026-09-04 [starforce.gg 계산 결과](https://starforce.gg/ev)와 대조한 출처 지문도 별도로 보존합니다. 사이트 코드를 런타임에 사용하거나 이식하지 않습니다. 이번 작업에서 그 사이트에 대한 새로운 검증을 했다는 의미는 아닙니다.

강화 기본 비용은 `1000 + 레벨³ × (현재 별+1)^지수 / 단계별 분모`를100메소 단위로 반올림합니다. 0~9성의 지수는1, 이후는2.7이며 단계별 분모는 JSON에 기록되어 있습니다. 파괴 방지를 켜면 할인 전 기본 비용의2배를 추가합니다. 할인 적용 후 비용도100메소 단위로 반올림합니다. 이 계산과 전체 별 보존 복구 메소 표의 정확도 상태는 beta입니다.

별 보존 복구 메소는 기록이 있는130/135/140/145/150/160/200/250제만 포함합니다. 다른 레벨로 보간하거나 확장하지 않습니다. 130/135제는 최대20성이므로15~19성 흔적만 필요합니다. 일반 시도 비용 모델의 입력 범위는1~250이며, 특수 장비의 실제 최대 별과 복구 재료는 따로 확인해야 합니다.

원본 JIJAKBI의 아스트라·데스티니 특수 복구 설정도 출처와 함께 보존하지만 일반 장비와 같은 것으로 추정해서는 안 됩니다. 장비 유형을 확정할 수 없다면 일반 모델에서 제외하거나 수동 일반 장비 선택을 사용해야 합니다.

이벤트 없음이 기본입니다. 선택 가능한 `샤이닝 스타포스 (15→16 확정 제외)`는 위 2026-09-06 행사의 세 효과와 직작비의 `shiningWithout1516` 규칙을 일치시켰습니다. 확정 성공을 추가하지 않으므로 5/10/15성도 기본 성공률을 유지합니다. 강화 비용은 기본 비용에0.7배, 파괴 방지 추가 비용에는 할인 전 기본 비용2배를 더해100메소 단위 반올림합니다. 파괴 방지 사용 시 총비용은 대략 기본 비용2.7배입니다. 현재21성까지만 파괴율을0.7배로 바꾸고 제거한 확률을 유지에 더합니다. 원래 단계 복구 메소만0.8배이며, 복구 장비 개수와 입력한 장비 단가는 할인하지 않습니다. 선택한 이벤트가 도전 전체에 유지되는 조건이며 실제 행사 진행 여부를 자동 판단하지 않습니다.

## 강화 루트 최적화

직작비 `src/Jijakbi.Calculation/StarforceCalculator.cs`의 단계별 정책 반복 방식을 사용합니다. 현재 일반 장비 레벨·목표·이벤트·장비 단가를 고정하고, 각 단계에서 파괴 방지를 켜거나 끄는 선택과 파괴 시12성 복구/흔적 단계 복구를 함께 비교합니다. 파괴 방지는15~17성에서만 후보이며, 원래 단계 복구는 내장 메소 표가 있는 레벨·흔적에만 후보입니다. 복구 비용이 없는 레벨에 수치를 보간하지 않습니다.

단계`s`에서 행동`a`의 즉시 기대비용은 `강화 메소 + 파괴확률 × (복구 메소 + 장비 개수 × 장비 단가)`입니다. 고정된 정책의 연립방정식 `V = r + P V`를 유리수로 풀고, 각 단계에서 자기 단계 반복을 제거한 `Q(a) = (r(a) + Σ[t≠s] P(a,t)V(t)) / (1−P(a,s))`를 비교합니다. 더 낮은 행동으로 교체한 뒤 다시 정확히 평가하며, 모든 단계에서 개선할 수 없을 때 끝납니다. 정확히 같은 비용이면 기존 행동을 유지합니다. 수십억 회 실제 강화나 제한된 표본 추정으로 최적 경로를 찾지 않습니다.

이 최소값은 해당 비용 모델에서 가능한 **단계별 파괴 방지·복구 정책**의 최소 평균 총비용입니다. 이벤트까지 기다리기, 장비 거래·교체, 강화권, 주문서, 특수 장비, 분산이나 파괴 횟수 최소화는 최적화 대상이 아닙니다. 시작 장비의 구매비는 이미 가진 장비로 보고 제외하고, 파괴 이후 복구용 장비만 과금합니다. 단가0은 복구용 장비를 이미 확보했거나 메소 가치로 세지 않는 조건입니다.

반환된 `config.policy`는0부터목표직전까지 모든 단계의 선택을 저장합니다. 실제 추첨·파괴 시점 복구 견적·기댓값이 모두 이 정책을 읽습니다. 시작 단계보다 낮더라도12성 복구로 되돌아갈 수 있는 단계까지 계산합니다. UI는 최종 정책에서 실제 방문할 수 있는 단계만 표시할 수 있습니다. 가격·목표·이벤트 변경 시 정책을 제거하고 다시 계산하며, 같은 조건의 재도전에는 저장된 정책을 그대로 사용합니다. 기존 설정은`event`와`policy`가 없는 평상시 수동 조건으로 계속 읽힙니다.

절감액의 비교 기준은 최적화 직전 수동 파괴 방지·복구 설정입니다. 수동 원래 단계 복구가 자료 없는 레벨이라 비교 계산이 불가능하면 비교 오류를 따로 표시하고 절감액을 만들지 않습니다. 가능한12성 복구 경로를 사용하는 최적화는 계속 계산합니다. 실제 지출은`BigInt`, 최적화 정책 비교는 유리수, 화면에 표시하는 평균과 비율만`number`를 사용합니다.

## 비용 분포와 행운

평균은 위 유리수 모형의 해석값을 사용하며 분포와 백분위만 고정 시드 500,000개 경로 표본으로 추정합니다. `src/engine/starforce-distribution.ts`는 직작비 `StarforceAggregateSampler.cs`의 전이 횟수 집계 방식을 이식합니다. 목표 직전 단계부터 아래로 내려가며 필요한 성공 횟수에 앞서 발생하는 파괴·하락·유지 횟수를 조건부 음이항 분포로 추첨합니다. 파괴 후 s에서 r로 돌아가면 r부터 s−1까지 필요한 성공 횟수를 추가합니다. 같은 단계 복구는 비용을 부과하되 추가 성공 횟수는 만들지 않습니다.

음이항은 Gamma–Poisson 혼합으로 뽑습니다. Gamma는 Marsaglia–Tsang, Poisson은 PTRS 거절 추출을 사용하며 개별 시도 수에 비례한 반복이나 정규분포 근사로 경로를 대체하지 않습니다. 공식 추첨·평균과 같은 `quoteStarforce`를 사용하므로 이벤트, 단계별 파괴 방지, 복구 정책, 복구용 장비 단가를 함께 반영합니다. 실제 메소 원장은 BigInt를 유지하고 분포 표본의 비용은 부동소수점 추정값입니다. 지원 범위를 벗어난 전이·안전한 정수 집계 범위 초과는 분포 오류로 표시하며 다른 분포를 대신 쓰지 않습니다.

Worker는 정렬한 비용 표본을 보관하고 성공 시 이분 탐색으로 `P(T ≤ 실제 총비용)`을 반환합니다. 같은 비용인 표본도 모두 포함합니다. 단순히 평균과의 비율로 백분위를 추측하지 않습니다. 실제 완료 비용의 백분위 P10 이하를 우선해 점프, 이후 평균의 90% 미만·90~110%·110% 초과 순서로 웃음·기본·울기 반응을 적용합니다. 완료 전이나 무료로 이미 달성한 시작에는 판정이 없습니다. 평균과 분포는 별도 메시지로 전달하여 분포 계산 중에도 강화는 진행할 수 있습니다.

`tests/starforce-distribution.test.ts`에서 독립적으로 비용별 확률 질량을 전파한 작은 모형의 CDF와 비교합니다. 자기 단계 복구, 하위 복귀, 파괴 비용과 강화 비용의 상관, 이벤트·파괴 방지·단계 정책, 동일 비용의 CDF 포함, 고정 시드 재현과 실제 30성 목표를 검증합니다. `STARFORCE_DISTRIBUTION_SAMPLES=500000`을 설정해 실행하면 30성 목표 두 복구 방식의 성능·해석 평균 대조를 `.cache/starforce-distribution-audit.json`에 기록합니다.

## 재생성과 검증

```sh
node scripts/sync-starforce.mjs
node scripts/sync-starforce.mjs --offline
npx vitest run tests/starforce-data.test.ts
```

원문 HTML8개, 샤이닝 안내 이미지1개, JIJAKBI 비용 참조와 교차검증 지문은 `public/rules/snapshots/starforce/`에 gzip으로 저장합니다. SHA-256은 압축 해제한 원문에 대해 계산하며 `public/rules/starforce.json`에 기록합니다. 새로 복제한 저장소에서도 오프라인 재생성이 가능합니다. 공식 이미지 해시가 달라지면 재생성 도구가 중단되어 혜택을 다시 확인하도록 합니다. 전체 확률 합, 경계 확률, 보너스 중복 적용 방지, 레벨 상한, 복구 재료 수량, beta 비용 출처 및 모든 스냅샷 해시를 테스트합니다.

## 캐릭터 스타포스 데이터

Nexon 장비 API의 실제 `starforce` 값만 0~30 정수로 보존합니다. 누락·잘못된 값은0으로 추정하거나 범위를 강제 보정하지 않고 미확인으로 둡니다. 이름/설명의 명시적 슈페리얼 표기는 `superiorEquipment`, `starforce_scroll_flag`의 사용/미사용 표기는 `extraordinaryStarforce`로 분리합니다. 이 두 필드의 부재는 확인되지 않았음을 뜻하며, 일반 강화 가능 장비임을 증명하지 않습니다.

기본 깽미니 스냅샷은 2026-09-18 05:01:48 KST에 API에서 조회한75개 프리셋 장비의 실제 스타포스를 이름·슬롯·레벨이 일치하는 항목에 보충했습니다. 다른 기존 데이터는 유지하며 별도 `starforceFetchedAt`을 기록합니다. 공용 서버와 개인 키 검색은 같은 정규화 함수를 사용합니다. 공용 서버는 응답 캐시 없이 매번 조회하므로 캐시 버전 변경은 필요 없지만 정규화 코드가 포함된 Worker 재배포가 필요합니다. 키와 원본 응답은 공개 파일에 포함하지 않습니다.
