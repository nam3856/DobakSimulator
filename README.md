# 이세계 직작

“이세계에서 내가 직접 돌렸다면 얼마나 썼을까?”를 체험하는 한국어 메이플스토리 시뮬레이터입니다. **2026-09-17 KMS 본서버, 평상시 확률**을 내장합니다. Vite + React + TypeScript로 만들었으며 서버나 API 키 없이 기본 캐릭터 **깽미니**로 실행됩니다.

[시뮬레이터 열기](https://nam3856.github.io/DobakSimulator/)

## 실행

Node.js 22.18 이상을 권장합니다. Windows PowerShell에서는 `npm` 대신 `npm.cmd`를 사용할 수 있습니다.

```sh
npm ci
npm run dev
```

개발 주소는 `http://127.0.0.1:5173`입니다. `npm run build`가 정적 배포용 `dist/`를 생성하며, `npm run preview`로 확인합니다.

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

브라우저 테스트는 빌드 결과를 `/DobakSimulator/` 하위 경로에서 직접 서빙합니다. 별도 서버나 Nexon 키가 필요하지 않습니다. 현재 화면과 진행 기록은 브라우저에 저장하고 API 키는 저장하지 않습니다.

## 도전하기

상단 메뉴는 **장비 강화**(큐브·추가옵션·스타포스), **어빌리티**(재설정·최적화), **소울**(증폭·잠재)의 2단 분류입니다. 분류 버튼은 메뉴만 펼치고, 세부 항목을 선택할 때 화면을 전환합니다. 분류를 둘러보는 동안 기존 도전 비용이나 진행 상태는 바뀌지 않습니다. 기존 탭 주소도 계속 열립니다.

### 추가옵션

`#bonusOptions`에서 장비 프리셋과 무기·방어구·장신구·포켓을 선택합니다. 현재 추옵과 무기의 **기본** 공격력·마력은 Nexon API에서 불러옵니다. 원본에 없는 수치를 0으로 추측하지 않으며, 예전 저장 데이터는 캐릭터를 다시 불러오면 보완됩니다. 기본 캐릭터의 과거 저장 기록은 장비가 정확히 일치할 때 빠진 추옵 정보만 보완하고 기존 강화 기록은 유지합니다.

메소 재설정·타오르는·검은·심연의 환생의 불꽃을 지원합니다. 환산 추옵 목표와 스탯별 환산 비율을 설정하고, 한 번씩 재설정하거나 목표까지 자동 진행할 수 있습니다. 매번 새 옵션을 즉시 적용하며, 직전과 완전히 같은 결과는 재추첨합니다. 목표 달성 후 **다시 진행**을 누르면 같은 설정과 선택 장비의 원래 추옵으로 돌아가 횟수·비용을 초기화하고 자동 진행합니다. 기댓값·분포·행운은 매회 현재 옵션 변경에 따른 동일 결과 제외 보정을 생략한 독립 시행 근삿값입니다. 아이템 가격을 0으로 두면 행운은 사용 횟수로 비교합니다. P95 이상은 공통 유령·묘비 연출을 사용합니다.

보스 장비 여부는 API에 없으므로 장비 이름에 따라 제안하며 직접 수정할 수 있습니다. 일부 고정 단계 장비는 특수 설정으로 입력합니다. 수치 모델과 지원 범위는 [추가옵션 규칙·출처](docs/bonus-option-sources.md)를 참고하세요. 기존 공용 서버도 새 장비 필드를 제공하려면 Worker를 함께 업데이트해야 합니다. 개발 환경은 `.env.development.local`의 `VITE_CHARACTER_API_URL=http://127.0.0.1:5173/api`로 새 로컬 API에 연결할 수 있습니다.

### 캐릭터와 링크

닉네임 검색에 성공하면 주소에 `?character=닉네임#탭`이 붙습니다. 이 주소를 공유하거나 즐겨찾기하면 해당 캐릭터와 탭으로 바로 열립니다. 주소의 캐릭터가 현재 저장된 캐릭터와 다르면 공용 API로 불러오며, 같은 캐릭터의 저장된 도전은 새로고침해도 이어집니다. 검색 결과는 실제 조회 시각부터 5분간 재사용하며, 즉시 갱신하려면 **최신 정보 다시 불러오기**를 선택하세요. 자동 조회에 실패하면 닉네임이 입력된 검색창에서 재시도하거나 개인 API 키로 검색할 수 있습니다.

메신저에 공유할 때는 캐릭터 아래 **캐릭터 링크 복사**를 사용하세요. 공용 서버의 `/share?character=닉네임&mode=탭` 주소를 복사하며, 미리보기에 **이세계의 닉네임으로 강화하기**가 표시되고 클릭하면 해당 캐릭터와 탭으로 이동합니다. 닉네임 끝 글자에 맞춰 `로/으로`를 선택합니다. 복사 권한이 없으면 직접 복사할 입력란을 제공합니다. 기존 GitHub Pages 주소도 계속 열리지만, 정적 HTML을 읽는 메신저에서는 공통 사이트 설명이 표시됩니다.

검색용 제목·설명, canonical, Open Graph/Twitter 메타 정보와 WebApplication 구조화 데이터는 `index.html`에 포함합니다. `public/sitemap.xml`은 대표 주소 하나를 안내하며 닉네임·탭별 중복 URL을 넣지 않습니다. Google Search Console에 제출할 사이트맵은 `https://nam3856.github.io/DobakSimulator/sitemap.xml`입니다.

단풍잎 아이콘은 헤더·로딩 화면·하단과 파비콘에 공통 적용합니다. `public/favicon.png`는 96px PNG이며, 32px PNG·ICO·Apple touch icon도 제공합니다. 원본과 제작 프롬프트는 [아이콘 제작 기록](docs/icon-design.md)에 있고, `npm run icons:build`로 크기별 파일을 다시 만듭니다.

도메인 루트 `https://nam3856.github.io/`용 정적 소개 페이지는 `site-root/`에 별도로 준비되어 있습니다. `npm run dev:root`로 `http://127.0.0.1:5174/`에서 확인할 수 있습니다. 루트 페이지는 같은 파비콘, 시뮬레이터 연결 버튼, 루트·시뮬레이터 주소를 담은 `sitemap.xml`과 `robots.txt`를 포함합니다. 실제 루트 도메인에 게시하려면 [루트 홈페이지 안내](site-root/README.md)에 따라 별도 GitHub Pages 저장소에 게시합니다. 프로젝트 경로의 `robots.txt`는 도메인 루트의 크롤링 설정을 대신하지 않습니다.

상단의 패러디 광고는 1·2·3·4번 배너 중 하나를 같은 확률로 보여주고, 1분마다 다른 배너로 바뀝니다. 1번은 새 경매장 이미지이며 클릭하거나 Enter를 누르면 [메이플스토리 경매장](https://auction.maplestory.nexon.com/)을 새 탭으로 엽니다. 2번은 스타포스 탭으로 이동합니다. 3번은 외부 링크 이동 확인창을 띄우며, 확인하면 [메이플스토리 이벤트 페이지](https://maplestory.nexon.com/News/Event/Ongoing/1389)를 새 탭으로 엽니다. 취소하면 이동하지 않습니다. 4번은 이미지 속 ‘키다리아저씨 고르기’를 누르면 [maplehooni 채널](https://www.youtube.com/@maplehooni), ‘남사친의정석 고르기’를 누르면 [땡 채널](https://www.youtube.com/@%EB%95%A1), 맨 아래 띠 영역을 누르면 [유튜브 영상](https://www.youtube.com/watch?v=IP4RacpJHu0)을 새 탭으로 엽니다. 어빌리티 최적화에서는 단계 입력에 집중할 수 있도록 배너를 숨깁니다.

1. 기본 깽미니 또는 검색한 캐릭터의 장비·어빌리티 프리셋 1~3을 선택합니다.
2. 업그레이드할 장비를 선택합니다. 기본 목표는 직업·부위에 맞는 유효옵션 합계 이상이며 화면의 조건으로 확인·수정할 수 있습니다. 방무는 복리, 주스탯 %는 올스탯을 합산합니다.
3. 모든 시뮬레이터는 **지금부터 업그레이드**로 고정되며 불러온 현재 등급·옵션·소울 단계에서 시작합니다. 시작 등급·옵션·실패 횟수를 직접 수정할 수 있고, 기댓값도 같은 시작 상태에서 계산합니다. **처음부터 직작하는 비용을 보려면 시작 등급을 레어로 바꾸세요.**
4. 실행 버튼 또는 자동 재설정을 누릅니다. 자동 실행은 **횟수 제한 없이 목표를 달성할 때까지** 진행하며, 중지 후 이어서 실행할 수 있습니다. **어빌리티·큐브·소울 잠재는 3회 비교가 기본**입니다. 큐브와 소울 잠재의 레어~유니크 구간은 1회씩 진행하고, 레전드리 도달 후 자동으로 3회 비교합니다. 세 후보는 같은 보관 옵션에서 생성하며 세 번 모두 과금합니다. 1회 모드도 직접 선택할 수 있습니다.
5. 성공 후 누적 비용·기댓값 대비 비율·백분위·캐릭터 반응을 확인합니다.

성공 기준의 `정확한 세 줄 재현`은 순서를 무시하고 표시 옵션의 종류·수치·중복 개수를 보존합니다. 모든 도전이 불러온 현재 상태에서 시작하므로 기본 목표가 이미 충족되어 있을 수 있습니다. 이때 목표 수치·등급·단계를 높여주세요.

예전 현재 옵션 재현 방식으로 저장된 도전은 현재 캐릭터의 등급·옵션·소울 단계에서 비용 0의 새 도전으로 전환합니다. 큐브·소울은 기존 목표·실행 단위·단가를 유지하고, 어빌리티는 현재 직업의 종결 목표를 적용합니다. 이전 기록은 보관하고 과거 비용을 새 기댓값과 섞지 않습니다.

목표 미달 결과는 보관 옵션에 적용하지 않습니다. 등급 상승과 목표 달성 결과는 적용합니다. **어빌리티 아랫줄 우선 방식에서는 목표 보조 줄을 확보한 결과도 채택하고 자동으로 잠급니다.** 다른 후보를 직접 채택하거나 목표·잠금·실행 단위를 바꾸면 현재 상태에서 비용 0의 새 도전이 시작됩니다. 자동 잠금은 도전을 이어가며 누적 비용과 최초 출발 상태의 기댓값을 유지합니다. `새 도전`은 같은 시작 상태의 도전을 초기화합니다. 단가 변경은 기록을 초기화하지 않습니다.

목표 달성 후에는 자동 실행 버튼이 `다시 자동재설정`으로 바뀝니다. 누르면 완료 기록을 보관하고, 같은 시작 옵션·등급·단계·실패 누적·목표·실행 단위에서 비용 0으로 다시 자동 실행합니다. 진행을 중지한 경우에는 `자동 재설정`으로 이어서 실행하며, 시작부터 목표를 만족한 무료 완료에는 다시 실행 버튼을 표시하지 않습니다.

## 어빌리티 종결 프리셋과 자동 잠금

### 어빌리티 최적화 탭

**어빌리티 최적화**에서는 시작 안내를 거쳐 현재 어빌리티·목표 옵션·보유 재화를 차례로 입력합니다. 캐릭터 프리셋을 조회하거나 현재 세 줄을 직접 입력할 수 있습니다. 목표 옵션 1은 레전드리이며, **목표 옵션 2·3은 각각 선택 안 함·유니크·레전드리** 중에서 고를 수 있습니다. 선택한 등급의 최대 수치를 기준으로 1~3개의 목표만 계산하고 최종 줄 순서는 무관합니다. 유니크 목표는 목표 수치를 충족한 레전드리도 성공으로 인정합니다. 현재 보유 옵션에서 시작하며, 직업별 종결 조합을 선택하면 세 레전드리 목표를 채웁니다. 시작 화면에서는 저장된 캐릭터가 walk1의 1→2→3→2 순서로 걷고, 해당 직업의 추천 옵션이 캐릭터 뒤에서 왼쪽 끝부터 오른쪽 끝까지 지나갑니다. 5초마다 다른 캐릭터로 부드럽게 전환해도 이미 나온 옵션은 끝까지 이동하며, 새 옵션부터 바뀐 직업을 반영합니다. 닉네임·직업명은 표시하지 않습니다. 탭이 숨겨지면 멈추고, 모션 감소 설정에서는 캐릭터와 옵션을 정지 상태로 보여줍니다.

기본 세 캐릭터의 이미지와 직업 정보는 로컬 자료만 사용합니다. 이미 조회한 캐릭터가 있으면 기존 직업과 이미지 주소로 걷기 프레임을 구성해 순환 목록에 추가하며, 동일 닉네임은 중복으로 넣지 않습니다. 이때 캐릭터 정보 API는 다시 호출하지 않지만, 해당 캐릭터의 걷기 이미지는 저장된 이미지 주소로 불러옵니다. 직업 추천이나 걷기 이미지 주소를 사용할 수 없는 캐릭터는 추가하지 않습니다. 닉네임 공유 링크도 시작 버튼을 누른 뒤 필요한 조회를 합니다.

명예의 훈장(명성치 5,000)과 심연의 서큘레이터의 개당 메소 가격을 입력한 뒤 `계산`을 누릅니다. 기본값은 **훈장 400만 메소·서큘레이터 2억 메소**이며 저장된 사용자 가격과 명시적인 0은 유지합니다. 재설정으로 목표 수치를 직접 맞추는 방법과 목표 종류·등급 확보 후 서큘레이터로 수치를 완성하는 방법을 비교하며, 세 목표에서는 아랫줄부터 서큘레이터로 완성하는 방법도 비교합니다. 세 레전드리 목표는 기존의 최초 잠금 집합 7가지와 3가지 완성 방식을 유지합니다. 현재 첫 줄이 목표를 만족하면 그 줄을 고정하는 방법도 추가합니다. 결과는 방법별 최저 예상 추가비용순으로 묶고, 펼치면 실제 옵션명으로 첫 잠금 조건과 진행 순서를 설명합니다. 재설정만 쓰면 목표 등급·수치를 충족할 때, 서큘레이터를 쓰면 목표 종류·등급을 확보했을 때 잠급니다. 추천은 비교한 전략 중 예상 추가비용이 가장 낮은 방법입니다.

예상 추가비용에는 재설정의 고정 메소, 필요 명성치 기댓값에서 보유 명성치를 뺀 부족분의 훈장 비용, 서큘레이터 비용을 포함합니다. 이는 개별 도전의 추가 구매비용을 정확히 평균한 값이 아닌 평균 필요량 기준 추정치이며 훈장 환산 수량은 소수일 수 있습니다. 3회 비교가 기본이며 세 번 모두 비용을 계산합니다. 가격·목표·프리셋을 변경하면 이전 결과를 지우고 다시 계산하며, 가격·보유 명성치만 바뀌면 자원 기댓값을 재사용합니다. 계산은 별도 Web Worker에서 수행하고 취소할 수 있습니다. 설정은 별도 저장 공간에 보관하며 `#abilityOptimizer` 주소로 바로 열 수 있습니다.

현재 프리셋에 선택한 목표 종류와 등급이 모두 있고 수치만 미완성이라면 **지금 옵션 그대로, 수치만 완성** 경로를 따로 비교합니다. 종류 확보를 위한 재설정 횟수·메소·명성치는 0이며, 목표 수치를 동시에 만족시키는 서큘레이터 개수와 비용만 계산합니다. 이 경우 같은 경로가 되는 최초 잠금 조건은 한 개로 합칩니다. 다른 방법과 함께 비교하므로 서큘레이터 단가에 따라 추천이 달라집니다. 목표에서 제외한 줄이나 이미 완성된 줄도 서큘레이터 사용 시 함께 재추첨하지만 패시브 스킬 레벨 +1처럼 값이 하나뿐인 옵션은 그대로입니다. 미달 결과는 이전 세 줄을 유지합니다. 선택한 목표를 이미 모두 만족하면 추가 비용은 0입니다.

[공식 서큘레이터 자료와 보관 원문](docs/ability-circulator-sources.md)을 포함합니다. 확률과 기댓값 계산에서는 등급·종류·수치 추첨, 중복 종류 제한, 완전히 같은 결과 제외, 이전 옵션 보관, 서큘레이터의 세 줄 동시 수치 변경을 반영합니다.

### 어빌리티 시뮬레이터

어빌리티는 **지금부터 업그레이드**로 고정되며, 불러온 캐릭터의 선택한 어빌리티 프리셋에서 시작합니다. 처음 열거나 다른 캐릭터를 검색하면 해당 직업의 종결 프리셋이 자동 선택되고 실제 목표에도 적용됩니다. 저장된 업그레이드 도전은 수정한 목표와 진행 상황을 복원합니다.

48개 직업의 종결 조합은 사용자가 제공한 표를 반영합니다. `직업별 종결 어빌리티`에서 다른 직업을 선택하거나 `내 직업 종결 적용`으로 되돌릴 수 있으며, **세 줄 모두 레전드리 옵션의 최저 수치**로 목표를 설정합니다. 수치를 높여 최대치에도 도전할 수 있습니다. 패=패시브 스킬 레벨, 재=재사용 대기시간 미적용, 상=상태 이상 대상 데미지, 보=보스 데미지, 크=크리티컬 확률, 공=공격력 또는 마력입니다. 공격력·마력은 선택한 프리셋의 직업에 맞춥니다. 첫 글자는 첫 번째 줄이며, 뒤의 두 옵션은 2·3번째 줄 순서가 바뀌어도 성공입니다.

목표 수치는 표시된 최저·최대 범위 안으로 자동 보정합니다. 어빌리티는 옵션·등급·줄에 맞는 범위를 사용하며, 큐브와 소울 잠재는 기존 기본 목표를 유지하고 합계 목표의 범위만 보정합니다.

기본 진행은 **보조 목표 중 하나를 2·3번째 줄에서 확보 → 해당 줄 잠금 → 남은 보조 목표 확보·잠금 → 첫 줄 완성**입니다. 종류·등급·목표 수치를 모두 만족해야 잠그며 첫 줄은 자동 잠그지 않습니다. 두 보조 줄이 함께 뜨면 둘 다 잠그고, 이미 목표 보조 줄이 있는 시작 상태는 무료로 잠근 뒤 진행합니다. 첫 줄까지 함께 완성되면 즉시 성공합니다. 잠금 0·1·2줄의 매회 비용은 각각 200만·600만·1,500만 메소와 명성치 2만·3만·4만입니다.

`어빌리티 목표 줄 수`에서 **2줄**을 선택하면 첫 줄 목표와 보조 목표 하나만 맞춥니다. **2·3번째 줄 중 하나에 보조 목표 확보 → 그 줄 잠금 → 첫 줄 완성** 순서이며, 남은 한 줄은 어떤 옵션이어도 됩니다. 보조 옵션은 직접 변경할 수 있고, 직업 프리셋을 바꿔도 선택한 2줄 설정을 유지합니다. 기존 3줄 목표에서 보조 조건 하나를 삭제해도 같은 방식으로 진행합니다. 기댓값에는 남은 자유 줄의 추첨·중복 제한과 1줄 잠금 비용을 반영합니다.

첫 줄을 이미 확보했다면 `어빌리티 진행 방식 → 첫 줄 고정 → 보조 줄 자동 잠금`을 선택합니다. **첫 줄을 유지하며 2·3번째 줄 추첨 → 보조 목표 하나 확보·잠금 → 남은 보조 줄 완성** 순서이며, 목표가 2줄이면 보조 옵션 하나를 얻는 즉시 완료합니다. 첫 줄이 현재 목표를 만족하지 않으면 안내를 표시하므로 시작 옵션이나 목표를 맞춰주세요. 기댓값에는 첫 줄 확보 비용을 제외하고 1·2줄 잠금 비용과 같은 추첨 규칙을 적용합니다. 자동 실행·중지·저장 복원·다시 자동재설정에서도 첫 줄 고정을 유지하며, 직업 프리셋이나 목표 줄 수를 바꿔도 이 진행 방식을 유지합니다.

어빌리티는 기본으로 3회 재설정하며 1회로 바꿀 수 있습니다. 3회 비교는 같은 보관 옵션·잠금으로 후보 세 개를 만든 뒤 전체 비용을 계산합니다. 완성 결과를 우선하고, 없으면 보조 줄을 더 많이 확보한 결과를 채택하며 동률이면 먼저 나온 결과를 선택합니다. 기댓값은 같은 시작 옵션·목표·자동 잠금·실행 단위에서의 평균 총비용입니다. 평균은 해석 계산하고 비용 분포는 고정 시드 50만 개 역누적분포 표본으로 추정합니다.

현재 보관 옵션 오른쪽 버튼으로 최대 두 줄까지 직접 잠그거나 해제할 수 있습니다. 직접 1·3회 재설정은 선택한 잠금을 유지합니다. 기본 `자동 재설정`은 2·3줄 어빌리티 목표를 확인해 불필요한 잠금을 풀고, 맞는 보조 줄을 잠근 뒤 아랫줄 우선 방식으로 진행합니다. 첫 줄을 계속 유지하려면 위의 `첫 줄 고정` 방식을 선택하세요. 수동에서 자동으로 전환할 때는 현재 옵션에서 새 도전을 시작하고 기댓값도 다시 계산합니다.

정확한 세 줄 재현이나 자유 조건처럼 자동 잠금 순서를 정의할 수 없는 목표는 `수동 잠금 유지` 방식으로 진행합니다.

## 지원 기능

### 스타포스

여섯 번째 **스타포스** 탭(`#starforce`)에서 캐릭터 장비 프리셋과 장비를 선택합니다. API가 제공한 실제 강화 단계에서 시작하며 시작·목표 단계를 직접 수정할 수 있습니다. 지원 범위는 1~250레벨 일반 장비이며 슈페리얼·놀장·특수 무기·특수 반지는 제외합니다. 수동 일반 장비 설정도 제공합니다.

`강화하기` 또는 `자동 강화`로 한 번씩 강화합니다. 초반 단계는 빠르게, 목표 직전에는 결과를 조금 더 길게 보여주며 화면에 속도 수치를 표시하지 않습니다. 자동 강화 중 `연출 스킵`을 누르면 같은 확률과 비용으로 목표까지 연출 없이 진행합니다. 준비 중인 시도는 한 번만 추첨하고 이미 나온 결과를 다시 과금하지 않습니다. `중단`은 마지막으로 확정된 진행을 보존하며, 중단 후 재개하거나 완료 후 `다시 자동 강화`를 누르면 기본 연출로 돌아갑니다. 현재 본서버의 단계 하락 없는 확률과 상시 스타캐치 보너스를 적용합니다. 파괴 방지는 15~17성에서 기본 비용의 2배를 추가하여 총 3배가 됩니다. 파괴 시 12성 복구 또는 흔적 단계(최대 22성) 복구를 선택하며 자동 실행은 복구 후 이어갑니다.

**샤이닝 스타포스(15→16성 확정 제외)**는 강화비 30% 할인, 21성 이하 파괴 확률 30% 감소, 흔적 단계 복구 메소 20% 할인을 적용합니다. 파괴 방지 추가 비용과 복구용 장비값은 할인하지 않습니다. 이벤트 선택은 도전 전체에 적용하며 실제 행사 날짜와 연동하지 않습니다.

`강화 루트 최적화`는 직작비처럼 단계별 파괴 방지와 두 복구 방식을 함께 비교해 평균 총비용이 가장 낮은 정책을 찾습니다. 계산 완료 시 현재 시작 설정의 새 도전에 적용하며 단계별 루트를 펼쳐 볼 수 있습니다. 계산 취소는 기존 진행을 유지합니다. 최적 정책은 재도전·저장 복원에도 적용되며, 장비·시작·목표·단가·이벤트 등 설정을 바꾸면 해제됩니다.

강화 메소·복구 메소·복구용 동일 장비값을 모두 기댓값과 행운 판정에 포함하고 비용 원장을 분리해 표시합니다. 장비 단가 0은 보유 장비를 사용하는 경우입니다. 기댓값은 Web Worker에서 유한 상태 모형으로 해석 계산하며, 실제 재화는 BigInt로 누적합니다. 최근 100회와 진행 상태를 별도로 저장하고 탭 전환·새로고침 시 복원합니다. 같은 시작·목표·이벤트·정책의 비용 분포를 고정 시드 **50만 경로 표본**으로 추정하고 그래프·P10/P50/P90·성공 비용의 백분위를 표시합니다. 개별 강화를 수십억 번 반복하지 않고 전이 횟수를 집계해 희귀 목표도 계산합니다. 평균이 먼저 나오면 분포 계산 중에도 강화할 수 있습니다.

성공 후에는 아래 공통 행운 기준으로 캐릭터가 반응합니다. 상위 10%에는 “아 게임에서 돌릴걸..” 등의 신나는 멘트, 평균 이하에는 “어? 생각보다 얼마 안 썼네?”·“이 정도면 꽤 싸게 먹혔다!”, 평균 근처에는 담담한 멘트, 평균 초과에는 “그래.. 이거면 된거야..”·“아무튼 내가 이긴거야..” 같은 멘트를 표시합니다. 진행·중단·이미 목표인 무료 시작에는 최종 행운 판정을 하지 않습니다.

**확률은 공식 자료, 강화·단계 보존 복구 비용은 검증 모델(베타)**입니다. 단계 보존 복구는 기록된 장비 레벨만 허용하고 미확인 레벨은 12성 복구를 안내합니다. 상세 출처·재생성 방법·제한은 [스타포스 규칙 출처](docs/starforce-sources.md)를 참고하세요.

| 골드큐브            | 명장의 큐브 확률, 이전 결과 보관, 상승 보장 없음, 큐브 개수 |
| 프라임큐브          | 레전드리 윗잠재 첫 줄 고정, 큐브 개수 + 10,000 크레딧/회    |
| 프라임 에디셔널큐브 | 레전드리 아랫잠재 첫 줄 고정, 큐브 개수 + 20,000 크레딧/회  |
| 소울 증폭           | 0~4단계, 실패할수록 확률 증가, 단계별 메소 + 에테르         |
| 소울 잠재           | 증폭 1~4단계, 레어~레전드리 전체 옵션, 메소 + 상승 보장     |

프라임은 **첫 줄 확보 후** 시작하며 준비 비용을 포함하지 않습니다. 소울의 직접 설정은 200레벨 이상, 위대한 소울을 장착한 영구 무기를 전제로 합니다. 공식 조회가 지원하지 않는 큐브 장비 조합은 다른 확률을 대신 적용하지 않고 사용할 수 없다고 표시합니다.

공용 서버가 연결되어 있으면 **닉네임만 입력해 검색**합니다. 운영자 Nexon 키는 Cloudflare Worker Secret에 보관합니다. 검색창에서 `개인 키로 전환`을 선택하면 개인 [Nexon Open API 키](https://openapi.nexon.com/ko/guide/prepare-in-advance/)를 사용할 수도 있습니다. 개인 키는 현재 탭의 메모리와 Nexon 요청 헤더에만 사용합니다. 공용 서버를 설정하지 않은 정적 배포는 개인 키 검색을 제공합니다. API가 제공하지 않는 연속 실패 수는 0으로 시작하며 직접 수정할 수 있습니다. 미확인 직업이나 누락 정보는 목표를 수동으로 설정하세요.

공용 서버는 **Cloudflare Workers 무료 요금제**로 배포되어 있으며 현재 사이트 설정에 연결되어 있습니다. 로컬 API를 따로 사용하려면 `.env.local`에 `NEXON_API_KEY`와 `VITE_CHARACTER_API_URL=http://127.0.0.1:5173/api`를 설정합니다. 공개 배포의 연결 주소는 `public/app-config.json` 또는 Actions 변수 `VITE_CHARACTER_API_URL`에 설정합니다. [공용 키 설정·배포 안내](docs/shared-api.md)를 참고하세요.

## 비용과 반응

기댓값은 같은 시작 상태·목표·잠금·실행 단위로 성공하기까지의 무조건부 평균 비용입니다. 메소 방식은 메소, 아이템 방식은 큐브 개수로 비교합니다. **소울 증폭은 강화 메소 + 소비 에테르의 입력 단가 환산액**을 기댓값·백분위·행운 판정에 함께 반영합니다. 에테르 기본값은 1단계 15억, 2단계 20억, 3단계 12억, 4단계 40억 메소입니다. 가격을 바꾸면 진행 기록을 유지하면서 실제 총비용과 분포를 다시 계산합니다. 기존 저장의 누락·빈 단가는 이 기본값으로 채우고, 직접 입력한 0을 포함한 단가는 유지합니다. 명성치·크레딧·큐브 시세 환산액과 각 자원 수량은 별도로 표시합니다. 실제 누적 재화는 `BigInt`, 확률과 평균은 부동소수점입니다.

성공 시 아래 순서로 판정합니다. 백분위는 `P(T ≤ 실제 비용)`이며 숫자가 작을수록 적은 비용으로 성공한 결과입니다.

| 조건              | 반응                                                 |
| ----------------- | ---------------------------------------------------- |
| 누적분포 P95 이상 | 유령으로 둥둥 떠 있기 (`A35/E00`) + 뒤쪽에 묘비 낙하 |
| 누적분포 P10 이하 | 웃으며 점프 (`A06/E02`)                              |
| 평균의 90% 미만   | 웃으며 서기 (`A00/E02`)                              |
| 평균의 90~110%    | 기본 서기 (`A00/E00`)                                |
| 평균의 110% 초과  | 울면서 엎드리기 (`A04/E03`)                          |

P95 이상이면 비용 비율보다 유령 반응을 먼저 적용합니다. 큐브·어빌리티·소울 증폭·소울 잠재·스타포스에서 같은 기준을 사용하며, “이세계여서 다행이다…”라는 멘트와 함께 캐릭터 뒤쪽에 묘비가 떨어지고 유령 캐릭터가 계속 떠 있습니다. 백분위는 반올림 전 값으로 판정합니다.

진행 중·중단·이미 달성한 시작 상태에는 최종 판정이 없습니다. 도달 불가능하거나 성공 확률이 1보다 작은 목표에는 유한한 기댓값을 표시하지 않습니다. 이미지 실패 시 기본 외형을 사용하며 모션 감소 설정에서는 유령과 묘비를 정지 상태로 표시합니다.

평균과 단순 분포는 해석적으로 계산합니다. 복합 분포는 고정 시드 500,000개 역누적분포 표본을 사용하고 추정 분포로 표시합니다. 희귀 목표의 개별 실패 시행을 수십억 번 반복해 평균을 구하지 않습니다. 자세한 계산·제한은 [확률 모형](docs/probability-model.md)을 참고하세요.

큐브·소울 잠재를 낮은 등급에서 시작하는 3회 모드의 기댓값에는 등급 상승까지의 1회 실행과 레전드리 이후의 3회 비교 비용이 모두 포함됩니다. 등급 상승한 순간 목표도 완성되면 그 1회 비용으로 종료합니다.

## 데이터와 갱신

- `public/rules/`: 실행 시 사용하는 정규화한 공식 확률 스냅샷.
- `public/rules/snapshots/`: 조회 응답의 표시 확률·원문·기존 직작비 스냅샷. 웹 실행 중에는 내려받지 않습니다.
- `public/rules/manifest.json`: 범위·검증일·SHA-256·출처. 큐브 세 종류 × 25 레벨 구간 × 20 분류 × 4 등급 = 6,000개 조회 조합을 기록합니다. 각 종류당 1,448개 사용 가능, 552개 공식 미제공입니다.
- `public/character/`: 실제 깽미니의 조회 시점 스냅샷과 공식 반응 이미지 5종. 조회 날짜는 파일의 `fetchedAt`입니다.

기존 [직작비](../JIJAKBI/README.md)의 공식 자료·옵션 정규화·추천 계열·검증 모형을 이식했습니다. 큐브 조회 중 344개는 기존 스냅샷을 재사용하며 해당 조회의 원래 확인일을 보존합니다. 나머지는 2026-09-17에 보충했습니다. 실행 시 최신 확률을 자동 조회하지 않습니다.

```sh
# 네트워크 없이 보관된 큐브 응답에서 재생성
npm run data:sync -- --offline
# 모든 큐브 표를 공식 사이트에서 다시 조회; 중단 후 재실행하면 이어짐
npm run data:sync -- --refresh --concurrency 3
# 보관된 어빌리티 원문에서 재생성
node scripts/rules-ability.mjs --offline
```

새 패치에 맞춰 갱신할 때는 등급 상승률·비용·규칙 버전도 함께 검토하고 테스트를 실행해야 합니다. 소울 자료는 보관한 공식 스냅샷과 대조해 갱신합니다. 캐릭터 갱신은 로컬 환경 변수 `NEXON_API_KEY`를 설정한 뒤 `npm run character:sync -- 깽미니`로 실행합니다. 키를 `VITE_*` 환경 변수나 공개 파일에 넣지 마세요.
